# Движок расчёта — `engine/calc.js`

Расчёт коммунальных услуг (КУ) и эксплуатационных расходов (ЭК) апарт-отеля TOR'RE Astana за месяц. Интерфейса и базы данных
в движке нет. Это один файл для пульта и для сервера: пульт, начисления с сервера (`GET /api/accruals`), корректировки
(`server/periods.js`) и проверка (`npm run check`) берут формулы отсюда. Других копий формул в проекте нет.

Правила расчёта — `docs/ПРАВИЛА РАСЧЁТА.md`; формат документа выгрузки — `docs/API.md`.

## Подключение

**Node (сервер, проверка, перенос в другой стек):**

```js
const { calcMonth, createEngine } = require('./engine/calc.js');

// данные месяца — ответ GET /api/state?period=2026-06 (на сервере: server/accruals.js, stateOf)
const r = calcMonth(state, '2026-06');
if (r.errs.length) throw new Error(r.errs.join('\n'));
r.env.documents;          // квитанции КУ и ЭК со строками, корректировочные
r.env.totals;             // итоги по дому и по плательщикам
r.units['5017'];          // { KU: [39022.83], EK: [20230.8], payer: 'owner' }
r.balance.water.perUnit;  // ОДН воды на помещение, м³

// отдельные формулы — в своём контексте движка
const E = createEngine();
E.payRound(-613.75);                // −614: переплата 614 ₸
E.acctMap(unit);                    // счета квитанций «собственник + плательщик»
E.carryFromDelta(E.fieldDelta(before, after));  // перенос корректировки в ОДН
```

`createEngine()` создаёт новый контекст: данные месяца в нём свои, расчёты в разных контекстах друг другу не мешают.
`calcMonth(state, per)` — расчёт в новом контексте.

**Браузер (пульт).** `public/index.html` подключает файл отдельным скриптом перед своим:
`<script src="/engine/calc.js"></script>`. Функции движка — глобальные. Данные месяца и поля ввода даёт пульт — см. «Хозяин»
ниже. Файл отдаёт сервер стенда.

## Вход — данные месяца (`MonthState`)

Ответ `GET /api/state?period=ГГГГ-ММ`. Типы полей — JSDoc в начале `calc.js`.

| Поле | Что это |
|---|---|
| `period` | месяц, за который у приборов собраны `prev` / `cur`; показания других месяцев — в `hist` |
| `rows` | помещения: номер, площадь, участие в ОДН, собственники (линия владения и ручные пометки разграничения `rz`), договоры управления `progs`, приборы `meters` с показаниями, договоры разграничения `rz` по ресурсам (вода `w`, электро `e`, тепло `h`) |
| `tariffs` | строки тарифов: услуга, тариф без НДС, НДС, с / по |
| `external` | доходные контрагенты с отметками «Учит.» — образец для нового месяца |
| `settings.byPeriod[месяц]` | вводные месяца: счета-фактуры `inW`, `inE`, `heat1` (вторые позиции при смене тарифа `inW2`, `inE2`, `heat2`, суммы `…Amt`), нужды ЭК `ukW`, `ukE`, `ukH`, «ЭК берёт из ОДН» `ek`, общая площадь здания `bldArea`, доходные месяца `ext` |
| `settings.heatByPeriod[месяц]` | Гкал месяца из импорта ЭСФ |
| `settings.applyRz`, `settings.ukPays` | переключатели «применять договоры разграничения» и «компания платит КУ за помещения в управлении» |
| `closed`, `closedPeriods`, `lastClosed` | снимок закрытого месяца (если месяц закрыт) и список закрытых |
| `adjustments`, `carries` | корректировки закрытого месяца; корректировки с переносом в ОДН этого месяца |
| `credits`, `offsets` | переплаты собственников; зачёты и возвраты переплаты |

## Выход — `MonthResult`

| Поле | Что это |
|---|---|
| `errs` | ошибки данных (например, плательщик не из трёх значений); есть — документа нет |
| `env` | документ выгрузки, схема 1.6 (`docs/API.md`): `documents` — квитанции КУ и ЭК по частям месяца со строками, ноль с причиной, долей счёта поставщика, строками «Перерасчёт» и «Зачёт переплаты», к оплате и переплатой; корректировочные; `totals` — итоги по дому, по плательщикам, по корректировочным |
| `units` | по помещению: `KU` и `EK` — суммы квитанций месяца (по частям), `payer` — плательщик месяца (`owner`, `uk`, `deduction`, `mixed`) |
| `balance` | баланс ОДН дома: вода и электроэнергия (счёт-фактура, в счёт УК, нужды ЭК, доходные, перенос, ОДН, на помещение / на м²), тепло (ЭСФ, общая площадь, разграниченные, база, коэффициент, тепло неразграниченных, нужды ЭК, перенос, остаток, ОДН на м²), компенсация «ЭК берёт из ОДН» |
| `ctx` | коэффициенты: `odnPerUnitW`, `odnPerAreaE`, `kOt`, `kOdn`, `ekFactor`, `nOdn`, `areaOdn`, `heatBaseArea`, `heatRest` |

## Порядок расчёта месяца

1. **Данные месяца.** Помещения без помеченных на удаление. Закрытый месяц — только помещения его снимка, расчёт — из снимка
   (`closedCtx`, `calcRowC`).
2. **Вводные месяца** — `monthInputs`:
   - новый месяц пустой: счёт-фактура и нужды ЭК пустые, «ЭК берёт из ОДН» 0, тепло — Гкал импорта ЭСФ;
   - доходные — свой список месяца; если его нет — по правилу 44б.
3. **Контекст месяца** — `buildCtx` → `buildCtxLive`:
   1. тарифы месяца: по дням (`tarOf`, `tarSegsOf`), НДС отдельно;
   2. первый проход по помещениям — объём «в счёт УК» по воде и электроэнергии, кто разграничен по теплу;
   3. ОДН воды = счёт-фактура − в счёт УК − нужды ЭК − доходные по воде − перенос; поровну на помещения базы ОДН;
   4. ОДН электроэнергии — так же, на м² площади базы ОДН;
   5. тепло (`heatSplit`): база = общая площадь здания − площадь разграниченных по теплу; коэффициент отопления = Гкал ÷ база;
      остаток = Гкал − тепло неразграниченных − нужды ЭК по теплу − перенос; ОДН тепла на м² = остаток ÷ площадь базы ОДН;
   6. «ЭК берёт из ОДН» — коэффициент, на который уменьшаются строки ОДН.
4. **Помещение** — `calcRow`:
   1. отрезки месяца — смены собственника и вход / выход из управления (`periodSegments`); у каждого отрезка свой плательщик:
      собственник, платит УК, из доли (`payerOfProg`);
   2. прибор: расход = (конец − начало) × коэффициент, отрицательный обнуляется (`meterUsage`). Промежутки по отрезкам
      (`meterIntervals`):
      - ручная пометка собственника этих дней сильнее договора (`ownerMark`);
      - договор, задевший месяц хоть одним днём, разграничивает весь месяц; по воде — с даты акта опломбировки (`rzCoverage`);
      - в дни, где платит УК или из доли, разграниченный объём «спит»;
      - в месяце продажи — доля счёта поставщика новому собственнику (`handSlices`);
   3. тепло — по площади и дням, так же через договоры и пометки (`heatIntervals`);
   4. квитанции — части месяца с одним собственником и одним плательщиком (`periodSplitCalc`):
      - строка услуги — на каждый тариф дней части, вверх до копейки;
      - ОДН — по доле дней;
      - ЭК — по площади и дням;
   5. итог месяца = сумма строк его квитанций.
5. **Документы** — `exportEnvelope`:
   - квитанции КУ и ЭК (`invoiceDocs`): строки, ноль с причиной (`zeroReason`), доля счёта поставщика, строки «Перерасчёт за …»
     и «Зачёт переплаты» своего собственника (`invSlots`), признак отрицательного расхода (`negativeUsage`);
   - к оплате — вверх до целого тенге; переплата — до целого по правилам математики (`payTotals`, `payRound`);
   - корректировочные квитанции закрытого месяца (`correctiveDocs`);
   - итоги.

## Хозяин в браузере

Пульт объявляет имена, которые движок читает при расчёте: данные месяца `ROWS`, `TAR`, `EXT`, `EXT_BASE`, `BY_PERIOD`,
`HEAT_BY_PERIOD`, `SETTINGS_LIVE`, `CLOSED`, `CLOSED_PERIODS`, `ADJ`, `CARRIES`, `CREDITS`, `OFFSETS`, `BASE_PERIOD`, контекст
`CTX` и доступ к полям ввода `el(id)`, `gv(id)`, `gc(id)`. Поля ввода месяца: `f-per`, `f-in-w`, `f-in-e`, `f-heat`, `f-in-w2`,
`f-in-e2`, `f-heat2`, `f-uk-w`, `f-uk-e`, `f-uk-h`, `f-ek`, `f-bld-area`, переключатели `f-rz`, `f-uk`. В Node эти имена задаёт
`calcMonth` из данных месяца. При переносе в другой стек их заменяет один объект входа.

## Соглашения

- Даты — строки `ГГГГ-ММ-ДД`, месяцы — `ГГГГ-ММ`, сравниваются как строки.
- Деньги: каждая строка квитанции — вверх до копейки, итог — сумма строк; к оплате — вверх до целого тенге.
- Объёмы: вода — 3 знака, электроэнергия — 2, тепло — 4.
- Номер прибора — `помещение|ресурс|серийный номер`.

## Проверка

`npm run check` считает тестовый набор июня 2026 (`tests/fixtures/2026-06`) этим движком и сверяет с `tests/etalon.json`:
КУ и ЭК по контрольным помещениям, итоги дома, ОДН и коэффициенты. Ожидаемый результат — «Расхождений: 0».
