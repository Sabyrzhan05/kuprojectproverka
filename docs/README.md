# Стенд расчёта коммунальных услуг TOR'RE Astana

Стенд считает коммунальные услуги (КУ) и эксплуатационные расходы (ЭК) апарт-отеля TOR'RE Astana (445 помещений) за месяц:
квитанции собственникам по помещениям, общедомовые нужды (ОДН), закрытие месяца и корректировки закрытых месяцев,
выгрузку квитанций для личного кабинета собственника.

Стенд — эталон для переноса в продакшен. Правила расчёта в нём утверждены заказчиком и сверены с расчётом бухгалтерии на
настоящих данных. Хранилище, сервер и интерфейс сделаны для работы одного оператора на одном компьютере и в продакшен не
переносятся как есть (раздел «Ограничения»).

## Состав

| Папка, файл | Что внутри |
|---|---|
| `engine/calc.js` | движок расчёта — один файл для пульта и сервера; описание — `engine/README.md` |
| `server/` | HTTP-сервер на Node.js без внешних зависимостей: хранилище (`db.js`), закрытие месяца и корректировки (`periods.js`), начисления за месяц (`accruals.js`), импорт показаний (`import.js`, разбор файлов — `parse_import.py`), очистка данных месяцев (`clean.js`) |
| `public/index.html` | интерфейс оператора (пульт): один файл, подключает движок `/engine/calc.js` |
| `data/` | база — JSON-файл на таблицу. В поставке — только справочники: помещения, собственники, приборы, договоры, тарифы, доходные контрагенты. Показаний, вводных месяцев, закрытых месяцев, корректировок и переплат нет (`docs/ОЧИСТКА ДАННЫХ.md`) |
| `Импорт/ГГГГ/ММ/` | файлы поставщиков по месяцам: АРЭК (электроэнергия), Су-Арнасы (вода), ЭСФ Теплотранзита (тепло); порядок — `Импорт/README.md` |
| `tests/` | тестовый набор июня 2026 (`fixtures/2026-06` — полная копия базы до очистки), эталон (`etalon.json`) и проверка (`check.js`) |
| `docs/` | документы (ниже) |
| `design/` | токены оформления пульта (`tokens.css`, `tokens.ts`), описание (`DESIGN.md`), снимки экранов (`screens/`) |
| `Запустить.bat` | запуск на Windows |
| `package.json` | команды `npm start`, `npm run check` |

## Запуск

Нужно:

- Node.js 18 или новее (проверено на 22 и 24);
- для импорта файлов поставщиков — Python 3 с пакетами `openpyxl` и `xlrd` (`python -m pip install openpyxl xlrd`).

Windows — двойной щелчок по `Запустить.bat`: откроется окно сервера и вкладка браузера `http://localhost:3000`. Пока окно
открыто, стенд работает.

Любая система:

```bash
npm start
```

Переменные окружения:

| Переменная | Что задаёт | По умолчанию |
|---|---|---|
| `PORT` | порт сервера | 3000 |
| `TORRE_DATA` | папка базы | `data/` рядом с сервером |

При запуске сервер приводит базу: начальное показание каждого прибора — конечное за прошлый месяц (правило 90 свода),
ручные пометки разграничения прежнего формата — к собственникам. Если что-то меняется, до этого делается копия базы
(`data/backup`). Пробовать код на настоящей базе — только на копии: `TORRE_DATA=<папка с копией> PORT=3002 npm start`.

## Проверка

```bash
npm run check
```

Считает тестовый набор июня 2026 движком (тем же путём, что `GET /api/accruals`) и сверяет с `tests/etalon.json`: суммы КУ и
ЭК по контрольным помещениям, итоги дома, ОДН и коэффициенты. Ожидаемый результат — «Расхождений: 0», код выхода 0. Набор
не трогает `data/`: копируется во временную папку.

Любая правка движка — `npm run check` до и после. Изменились суммы — это изменение правил: сначала решение заказчика и
запись в свод правил, потом новый эталон.

## Как начать работу с поставочной базой

1. Положить файлы поставщиков месяца в `Импорт/ГГГГ/ММ/` (`Импорт/README.md`).
2. В пульте выбрать месяц и открыть окно «Импорт показаний» («Показания» в левой панели или «Ещё ▾ → Импорт показаний…»):
   предпросмотр, предупреждения, запись. Для первого месяца
   начальные показания берутся из файлов: вода — из отчёта Су-Арнасы; электроэнергия — из самого раннего снимка АРЭК, поэтому
   в папке первого месяца нужны два снимка АРЭК — на конец прошлого месяца и на конец этого. При одном снимке импорт
   предупреждает, у скольких приборов нет начального показания.
3. Ввести вводные месяца в шапке: счета-фактуры, нужды ЭК, доходные. Проверить «Проверки за месяц».
4. Закрыть месяц: чек-лист, снимок. Дальше закрытый месяц меняется только корректировками.

Начисления за месяц для кабинета — `GET /api/accruals?period=ГГГГ-ММ` (`docs/API.md`). Месяц, которого в базе нет (ни
показаний, ни вводных, ни закрытия), — ответ 404: в поставочной базе так отвечает любой месяц, пока не загружены показания.

## Ограничения

- **Хранилище — JSON-файлы**, один процесс Node; пока считается месяц (около секунды), сервер не отвечает на другие запросы.
- **Входа нет.** Кто работает, оператор выбирает в верхней полосе без пароля; роль проверяется только по имени. Права —
  задача кабинета (`docs/ОТКРЫТЫЕ ВОПРОСЫ.md`, раздел 2).
- **Часть проверок делает только интерфейс** (баланс и тарифы при закрытии, остаток переплаты при зачёте, показание на дату
  передачи, коэффициент трансформации) — сервер кабинета должен делать их сам (там же).
- **Интерфейс — для оператора**, а не для собственника: кабинет показывает данные выгрузки и сам ничего не пересчитывает.
- **Часовой пояс сервера** должен совпадать с Астаной: местные даты (дата выставления ЭК, «сегодня») берутся из часов
  процесса.
- Известные ошибки стенда и вопросы без решения — `docs/ОТКРЫТЫЕ ВОПРОСЫ.md`.
