# Очистка данных месяцев

Функция убирает из базы данные выбранных месяцев: показания, вводные месяца, доходные месяца, переносы корректировок.
Справочники остаются: помещения, собственники, приборы, договоры, тарифы. Применяется перед загрузкой настоящих данных
и при повторной загрузке месяца с нуля.

- В стенде: «Ещё ▾» → «Очистить данные месяцев…».
- На сервере: `GET` и `POST /api/clean-months`, модуль `server/clean.js`.

## Кто может

Только «Руководитель» и «Бухгалтерия» — по выбору «Кто работает» в верхней полосе. Отделу «Работа с собственниками»
отказ — и в окне, и на сервере (ответ 403).

## Что удаляется и что нет

Удаляется — за каждый выбранный месяц:

| Таблица (файл базы) | Что удаляется | Поля |
|---|---|---|
| `readings` | показания приборов за месяц: начальное, конечное, на дату договора, на дату передачи | записи с `period` = месяц: `prev`, `cur`, `midRead`, `ownRead`, `prevSrc`, `prevNote` |
| `settings.byPeriod[месяц]` | вводные месяца: счета-фактуры по воде, электроэнергии, теплу (объёмы и суммы, вторые позиции при смене тарифа); нужды ЭК по воде, электроэнергии, теплу; «ЭК берёт из ОДН»; общая площадь здания месяца; доходные месяца (объёмы, отметки «Учит.») и их состояние | вся запись месяца: `inW`, `inE`, `heat1`, `heat2`, `inW2`, `inE2`, суммы `…Amt`, `ukW`, `ukE`, `ukH`, `ek`, `bldArea`, `ext`, `extSrc`, `src` |
| `settings.heatByPeriod[месяц]` | Гкал месяца из импорта ЭСФ | значение месяца |
| `settings` (поля шапки) | вводные выбранного месяца, которые страница повторяет в общих настройках, — если выбранный месяц очищается | `inW`, `inE`, `ukW`, `ukE`, `ukH`, `heatGcal`, `ek`, `bldArea`, суммы и вторые позиции |
| `adjustments` | переносы корректировок закрытого месяца в ОДН очищаемого месяца | `carry.water`, `carry.e`, `carry.heat` = 0; прежние значения — в `carryCleared` (`at`, `by`, `was`) |
| `offsets` | зачёты переплаты в квитанции очищаемого месяца | записи с `type` KU / EK и `period` = месяц |
| `imports` | протоколы импорта показаний за месяц | записи с `period` = месяц |

Не меняется:

| Таблица | Что остаётся |
|---|---|
| `units` | помещения, площади, этажи, типы, участие в ОДН |
| `owners` | собственники, линии владения (`from` / `to`), телефоны, e-mail, представители, ручные пометки разграничения (`rz`) |
| `meters` | приборы: серийные номера, ресурс, коэффициенты трансформации, даты установки и снятия, «участвует в расчётах», примечания |
| `contracts` | договоры разграничения, акты опломбировки (дата и номер), вложения |
| `programs` | договоры управления |
| `tariffs` | тарифы |
| `external` | список доходных контрагентов с отметками «Учит.» и признаком «по умолчанию не учитывается» — образец для новых месяцев |
| `replacements` | акты замены приборов |
| `closed_periods`, `adjustments` (кроме переносов) | закрытые месяцы и корректировки — закрытый месяц не очищается |
| `offsets` (тип REFUND) | отметки о возврате переплаты деньгами |
| `log`, `log_archive` | журнал изменений; очистка сама добавляет в него запись |
| `settings` (остальное) | пользователи, переключатели расчёта, отметки «проверено» и «просмотрено» |

## Особые случаи

- **Закрытый месяц** не очищается. Отказ с причиной, ничего не удаляется: снимок закрытого месяца неприкосновенен, данные
  закрытого месяца меняются только корректировкой. Чтобы очистить закрытый месяц, его сначала открывают заново
  («Открыть период заново…»; можно только последний закрытый и только без корректировок).
- **Акт замены прибора.** Показания, зафиксированные актом, — конечное снятого прибора и начальное поставленного — часть акта.
  Они остаются; остальные показания тех же записей удаляются. В окне — «показаний актов замены останется N».
- **Месяц после очищаемого**, если его не очищают:
  - начальные показания, внесённые вручную, поставленные корректировкой или актом, не трогаются;
  - начальные, перенесённые из конца очищаемого месяца (пометка «перенесено»), остаются числом, пометка снимается. Перенос
    начала их не сотрёт, а следующая загрузка очищенного месяца снова поставит начало = конец этого месяца.

## Порядок действий оператора

1. В верхней полосе выбрать, кто работает: «Руководитель» или «Бухгалтерия».
2. «Ещё ▾» → «Очистить данные месяцев…». В окне — месяцы, в которых есть данные, и по каждому: сколько показаний, есть ли
   вводные, сколько строк доходных, переносов корректировок, зачётов, записей импорта. Закрытые месяцы — серые, с причиной.
3. Отметить месяцы («выбрать все» — все незакрытые) → «Очистить выбранные…».
4. В окне «Вы уверены?» — что удалится по каждому месяцу → «Да, очистить».
5. Стенд делает копию базы («перед очисткой месяцев …»), удаляет данные, пишет в журнал строку «весь дом»: кто, какие месяцы,
   сколько удалено и имя копии.
6. Вернуть всё как было: «Ещё ▾» → «Вернуть копию…» → копия «перед очисткой месяцев …».

## Через API

Запись — с заголовком `X-User` (имя того, кто работает, в кодировке URI) и `Content-Type: application/json`.

```
GET /api/clean-months
→ 200 { "periods": [ { "period": "2026-06", "label": "июнь 2026", "closed": false, "readings": 1400, "readingsActKept": 0,
        "inputs": 1, "inputFields": 9, "heatImport": 1, "ext": 4, "carries": 0, "offsets": 0, "imports": 0,
        "nextCarriedStarts": 787, "nextManualStarts": 0 }, … ] }

GET /api/clean-months?periods=2026-06,2026-07
→ 200 { "periods": [ … ] }                — предпросмотр выбранных месяцев, база не меняется

POST /api/clean-months
X-User: %D0%A0%D1%83%D0%BA%D0%BE%D0%B2%D0%BE%D0%B4%D0%B8%D1%82%D0%B5%D0%BB%D1%8C
{ "periods": ["2026-06", "2026-07"] }
→ 200 { "backup": "…_перед очисткой месяцев 2026-06 2026-07", "by": "Руководитель",
        "periods": [ …числа по месяцам до очистки… ],
        "total": { "readings": 2789, "readingsActKept": 0, "inputs": 2, "ext": 4, "carries": 0, "offsets": 0, "imports": 0 } }
→ 400 — месяцы не указаны или не в виде ГГГГ-ММ
→ 403 — роль «Работа с собственниками» или пользователь не выбран
→ 409 — среди месяцев есть закрытый (ничего не удаляется)
```

## Загрузка нового месяца после очистки

1. **Показания.** Файлы поставщиков — в папку `Импорт/ГГГГ/ММ`: выгрузка АРЭК «Апартаменты ДД.ММ.ГГ.xlsx», отчёт Су-Арнасы,
   ЭСФ Теплотранзита. Затем «Ещё ▾» → «Импорт показаний» → предпросмотр → запись. Начальные показания первого месяца после
   очистки:
   - вода — начало и конец из отчёта Су-Арнасы: в стенде нет конца прошлого месяца, начало берётся из файла;
   - электроэнергия — выгрузка АРЭК даёт одно показание на дату. Начало первого месяца — из более ранней выгрузки АРЭК в той
     же папке (на конец прошлого месяца). Импорт берёт начало из самого раннего снимка, конец — из самого позднего. Если
     снимок один, предпросмотр предупреждает: «у N приборов нет начального показания». Их расход будет 0, а объём уйдёт в
     ОДН, поэтому положите вторую выгрузку или внесите начальные показания вручную;
   - тепло — Гкал и сумма из ЭСФ.

   Со второго месяца начало каждого прибора = конец прошлого месяца в стенде, начало из файла — только для сверки.
2. **Счета-фактуры и нужды ЭК.** Шапка месяца или «Настройки месяца»:
   - объёмы или суммы по счетам-фактурам воды и электроэнергии (тепло — из импорта ЭСФ);
   - нужды ЭК по воде, электроэнергии и теплу;
   - доходные месяца;
   - при необходимости «ЭК берёт из ОДН» и общая площадь здания.

   Пустые поля нового месяца подсвечены красным («нужно заполнить»); введённый 0 — тоже ввод.
3. **Проверка.** Шаг месяца «Проверка» и «Отчёты» → «Проверки за месяц»: приборы без показаний, отрицательный расход, баланс ОДН
   по воде, электроэнергии и теплу, тарифы на все дни месяца, переплаты.
4. **Закрытие.** «Закрыть период» → чек-лист закрытия → снимок. После закрытия месяц показывается из снимка, изменения — только
   корректировками.
