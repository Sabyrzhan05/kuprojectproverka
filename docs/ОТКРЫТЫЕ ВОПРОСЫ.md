# Открытые вопросы

Вопросы, по которым нет решения заказчика; проверки, которые в стенде выполняет только интерфейс; известные ошибки стенда.
До решения стенд считает по действующим правилам (`docs/ПРАВИЛА РАСЧЁТА.md`). Номера вопросов — те же, что в своде правил.

## 1. Вопросы заказчику

| № | Вопрос | Как сейчас в стенде |
|---|---|---|
| В1 | Продажа в месяце, разграниченном договором прежнего собственника (правило 46б) | Новому собственнику за его дни выставляется «доля счёта поставщика» через УК. При этом поставщик выставляет прежнему счёт за весь месяц, поэтому возможна двойная оплата. Варианты: как сейчас или у нового в месяце продажи этой услуги нет |
| В2 | НП8, вода | Договора разграничения по воде нет, в примечании прибора — «воду напрямую платят». Пока договора нет, вода НП8 начисляется в квитанции УК |
| В3 | Нужды ЭК по теплу: источник числа | Число вводит оператор каждый месяц. Источник — расшифровка ЭСФ Теплотранзита у бухгалтерии: в самом ЭСФ отдельной строки УК нет |
| В4 | Отрицательный расход: как показывать собственнику | Конец месяца меньше начала — расход прибора обнуляется. В квитанции собственника это не печатается. Оператору — значок ⚠ в пульте, отчёт «Проблемные показания» и пункт чек-листа закрытия. В выгрузке для кабинета — признак `negativeUsage` у документа КУ. Обнулённая разница не возвращается: начало следующего месяца равно концу этого. Если счётчик откатился, разница уходит в ОДН дома |
| В5 | Ресурс «тепло» в списке доходных | В «Доходных» можно выбрать ресурс «тепло», но расчёт такую строку не вычитает: тепло считается по ЭСФ, нуждам ЭК и площадям. Нужно уточнить: убрать «тепло» из списка или вычитать его из Гкал месяца |
| В6 | Договор нового собственника в месяце продажи | Договор разграничения, который новый собственник заключил в месяце продажи, разграничивает этот месяц целиком, в том числе дни прежнего собственника (правило 38). Если у прежнего своего договора не было, за свои дни он не платит |
| В7 | Общий выключатель «применять договоры разграничения» | Выключает и договоры, и ручные пометки разграничения (правило 12). В тексте подтверждения переключателя об этом не сказано |
| В8 | Переключатель «УК платит КУ за помещения в управлении» | Один на весь дом (правило 42). В исходном правиле — на договоре управления |

## 2. Для разработчика: проверки, которые должен делать сервер

В стенде эти проверки выполняет страница: окна не дают выполнить действие, а сервер принимает то, что прислала страница.
В кабинете их нужно делать на сервере.

| Действие | Проверка | Как сейчас в стенде |
|---|---|---|
| Закрытие месяца | Баланс сходится: ОДН воды и электроэнергии не меньше нуля, остаток тепла не меньше нуля, база отопления больше нуля. Тарифы: на все дни месяца, без пересечения строк, без нулевых. Иначе — только принудительное закрытие с причиной | Сервер смотрит отметки чек-листа, которые прислала страница (`server/periods.js`, `close`), и сам баланс и тарифы не пересчитывает |
| Зачёт переплаты | Сумма — не больше остатка переплаты собственника и не больше суммы к оплате квитанции. Собственник — из помещения | `POST /api/offsets` проверяет только формат суммы и то, что окно видело ту же сумму зачтённого (`seen`). Ограничение по остатку есть только в окне |
| Повторное открытие месяца | Роль — из входа пользователя: открыть может только «Руководитель» или «Бухгалтерия». Список пользователей и ролей правит только руководитель | Роль берётся по имени из заголовка `X-User` или из тела запроса, без пароля. Список пользователей хранится в настройках, и его может переписать любой запрос `PUT /api/table/settings` |
| Правка тарифов | Тариф 0, пересекающиеся строки, строка без даты «с» — отказ или явное предупреждение | `PUT /api/table/tariffs` принимает такие строки, пишет только журнал |
| Вводные закрытого месяца | Запись запрещена: закрытый месяц читается из снимка | `PUT /api/table/settings` принимает вводные закрытого месяца. На расчёт это не влияет, но шапка закрытого месяца показывает их, а не снимок |
| Показание на дату передачи | Между начальным и конечным показанием месяца | Проверяют форма помещения и форма корректировки. `PUT /api/unit` принимает любое |
| Коэффициент трансформации | Больше нуля | Не проверяется нигде. Отрицательный коэффициент даёт минус в квитанции, ноль считается как 1 |
| Продажа помещения | Договоры разграничения и договор управления прежнего собственника закрываются днём до передачи | Закрывает страница при правке владения. Расчёт закрывает их и без даты в базе (правило 46в). Запись мимо страницы оставляет в базе открытые договоры |
| Смена собственника | Одна смена в месяц | Проверяют и страница, и сервер стенда (`PUT /api/unit` — отказ 409). Перенести в кабинет |

## 3. Известные ошибки стенда

Найдены при проверке решений заказчика 06.10.2026, не исправлены. В данных стенда эти случаи не встречались или
встречались только на копиях базы при проверке. При переносе в кабинет — не повторять.

**Могут изменить суммы**

| № | Ошибка | Пример |
|---|---|---|
| 1 | Продажу перенесли на более позднюю дату — договоры прежнего собственника остаются закрытыми прежней датой | 5021: продажа 20.06 → 30.06, договоры остались «по 19.06» — дни 20–29.06 не разграничены |
| 2 | Автозакрытие при продаже закрывает и договор, записанный на нового собственника, и договоры, помеченные на удаление | НП2, модель: в июле 610 529,42 ₸ вместо 609 749,90 |
| 3 | Отмена ошибочной продажи пометкой нового собственника на удаление не возвращает договоры прежнего | 5021, модель: июль 13 518,93 ₸ платит собственник; без продажи — 8 721,15 ₸, платит УК |
| 4 | Перенесли дату передачи внутри месяца — внесённое показание на дату передачи не сбрасывается и применяется к новой дате | расчётом не доказано |
| 5 | Пустое ФИО или пробел в конце ФИО делит месяц на лишние квитанции | в базе 4 ФИО с пробелом по краю |

| 15 | Доходные: объёмы складываются без приведения к числу («10» + «5» = 105) | сейчас в базе все объёмы — числа |
